DashLab+

Guia completo para instalar, configurar e manter seu dashboard pessoal dentro do homelab.

Modelo single-user

O DashLab+ não possui contas ou autenticação própria. Publique-o apenas em uma rede confiável, atrás de VPN ou de autenticação no proxy reverso.

Visão geral

O DashLab+ é uma interface self-hosted para centralizar atalhos, acompanhar métricas e verificar a disponibilidade dos serviços da sua rede. Uma única imagem contém a landing, o Server Hub e a API Go.

A API serve os arquivos web, persiste o estado no SQLite e integra Prometheus, clima e serviços internos. Todo o estado persistente fica no volume Docker dashlab_plus_data.

01

Requisitos

  • Docker Engine 24 ou mais recente.
  • Docker Compose v2.
  • Um host Linux com acesso aos serviços monitorados.
  • Prometheus é opcional, mas necessário para widgets de CPU, memória, discos e rede.

O frontend é acessado pelo navegador e não requer instalação de Node.js no host de produção.

02

Instalação

1. Execute

curl -fsSL https://dashlabplus.vercel.app/install.sh | sh

O instalador verifica Docker e Compose, cria ~/.dashlab-plus, baixa a imagem oficial e inicia o container.

2. Configure, se necessário

Edite ~/.dashlab-plus/.env para alterar a porta ou conectar o Prometheus. Execute novamente o instalador para aplicar.

3. Confirme a saúde

curl http://IP-DO-HOST:3000/api/health

A resposta deve conter {"status":"ok","storage":"sqlite"}.

03

Variáveis de ambiente

VariávelPadrãoFinalidade
WEB_PORT3000Porta publicada pelo container.
PROMETHEUS_URL—URL acessível pelo container.
PROMETHEUS_TARGET_LABELSvazioLabels comuns ao host monitorado.
PROMETHEUS_NETWORK_LABELSdevice!="lo"Interfaces incluídas nas métricas de rede.
PROMETHEUS_DISK_LABELSNVMe e sdXDiscos incluídos nas consultas.

DATABASE_PATH, WEB_ROOT e PORT já são definidos pela imagem. Altere-os somente ao executar o binário Go fora do Docker.

04

Prometheus

A URL precisa ser resolvida de dentro do container dashlab-plus. Se o Prometheus estiver numa rede Docker compartilhada, use o nome DNS do serviço. Se estiver em outro host, use o IP da LAN.

PROMETHEUS_URL=http://192.168.15.20:9090
PROMETHEUS_TARGET_LABELS=instance="node-exporter:9100"
PROMETHEUS_NETWORK_LABELS=device=~"enp.*|eth.*",device!="lo"
PROMETHEUS_DISK_LABELS=device=~"nvme[0-9]+n[0-9]+|sd[a-z]+"

Consultas personalizadas

Quando seu exporter utiliza métricas diferentes, defina consultas completas com PROMETHEUS_CPU_QUERY, PROMETHEUS_MEMORY_QUERY, PROMETHEUS_DOWNLOAD_QUERY, PROMETHEUS_UPLOAD_QUERY, PROMETHEUS_DISK_INFO_QUERY, PROMETHEUS_DISK_UTILIZATION_QUERY, PROMETHEUS_DISK_READ_QUERY, PROMETHEUS_DISK_WRITE_QUERY, PROMETHEUS_DISK_TEMPERATURE_QUERY e PROMETHEUS_DISK_HEALTH_QUERY.

05

Primeiro uso

  1. Abra Personalizar para definir nome, cores, logo, favicon e wallpaper.
  2. Use Adicionar para cadastrar serviços e URLs de status.
  3. Crie widgets de sistema, clima, pesquisa ou PromQL.
  4. No desktop, ative Editar organização para mover e redimensionar itens.
  5. Escolha Grade, Menu lateral ou Barra inferior para o layout móvel.
  6. Instale o PWA pelo navegador quando desejar acesso semelhante a aplicativo.

Alterações são salvas imediatamente no SQLite e ficam disponíveis a todos os seus dispositivos.

06

Arquitetura

Navegador
   │
   ▼
DashLab+ :3000
   ├── Landing + Server Hub
   ├── API /api
   ├── SQLite /data/dashlab-plus.db
   ├── Prometheus
   ├── Open-Meteo
   └── serviços da LAN

Um único processo Go serve os arquivos React/Vite e o contrato HTTP consumido pelo dashboard. Ele serializa a configuração single-user no SQLite e guarda os assets no mesmo banco.

Por que uma API ainda existe?

O navegador não deve receber acesso direto ao Prometheus nem consegue verificar todos os serviços internos por causa de CORS. A API também garante que desktop e celular compartilhem o mesmo estado.

07

Persistência e backup

O volume dashlab_plus_data contém o banco e os arquivos auxiliares de WAL. Para uma cópia consistente, pare o container antes de copiar o volume:

docker stop dashlab-plus
docker run --rm -v dashlab_plus_data:/source -v "$PWD":/backup alpine \
  tar -czf /backup/dashlab-plus-data.tar.gz -C /source .
docker start dashlab-plus

Para restaurar, crie uma instalação limpa, pare o container e extraia o conteúdo no mesmo volume. Mantenha o backup fora do host do homelab.

08

Atualização

curl -fsSL https://dashlabplus.vercel.app/install.sh | sh

O instalador atualiza a imagem e recria somente o container. O volume SQLite permanece intacto. Faça um backup antes de atualizações importantes.

09

Segurança

Não exponha a aplicação diretamente à internet

Qualquer pessoa que alcance a interface também pode alterar seu dashboard. O modelo single-user considera a LAN, VPN ou autenticação externa como limite de confiança.

  • Prefira Tailscale, WireGuard ou outra VPN para acesso remoto.
  • Se usar proxy reverso público, exija autenticação antes de encaminhar qualquer rota, inclusive /api.
  • Não publique Prometheus, SQLite ou a porta 3001.
  • Mantenha imagens Docker e o host atualizados.
  • Use HTTPS quando houver tráfego fora da LAN.

10

Solução de problemas

Widgets exibem zero ou indisponível

Confira PROMETHEUS_URL, labels e conectividade a partir do container.

Um serviço aparece offline

A URL de status precisa ser acessível pela rede do container. Prefira um endpoint de saúde sem login interativo.

Alterações não permanecem

Verifique o volume e os logs com docker compose logs api. O container precisa escrever em /data.

PWA mantém conteúdo antigo

Recarregue ignorando cache ou remova e instale novamente o PWA.

Suporte

Abra uma issue no GitHub com versão, logs relevantes e passos para reproduzir, removendo informações sensíveis.
